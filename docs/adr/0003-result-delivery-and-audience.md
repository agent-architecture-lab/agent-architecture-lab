# ADR 0003. 명령별로 사용 권한과 결과 공개 범위를 정한다

## 맥락

결과 전달 Lambda는 지금 성공 여부에 따라 고정 문장 두 개 중 하나만 보낸다. 통합 서비스에서는 단계 결과(FAQ 답변과 출처, 평가 요약, 회고 피드백)를 실제로 보여 줘야 한다.

결과마다 볼 수 있는 사람이 다르다. 스크리닝 결과는 지원자의 개인 평가이므로 지원자나 다른 스터디원에게 보이면 안 된다. 회고 피드백은 작성자 본인을 위한 것이다.

Discord에서는 deferred 응답(type 5)을 보낼 때 응답을 본인에게만 보이게(ephemeral, `flags: 64`) 할지 정해야 하고, 이후 follow-up으로 원본 메시지를 수정해도 공개 범위는 바뀌지 않는다. 메시지 본문은 2,000자로 제한된다.

## 결정

1. 명령별 사용 권한과 공개 범위

   | 명령 | 사용 가능 | 결과 공개 범위 | 메시지 내용 |
   |---|---|---|---|
   | `/faq` | 모두 | 질문자 본인 (ephemeral) | 답변 + 출처 청크 ID + 공고 버전 |
   | `/screen` | 운영진 역할만 | 실행한 운영진 본인 (ephemeral) | 항목별 등급 요약, 검증 상태, 운영진 확인 필요 여부 |
   | `/retro` | 스터디원 | 작성자 본인 (ephemeral) | 잘한 점 / 다음 주 제안 / 질문 |

2. 1차 접근 제어는 Discord 명령 등록 시 `default_member_permissions`로 하고, 2차로 ingress Lambda가 interaction의 역할 정보를 확인한다. 권한이 없으면 워크플로를 시작하지 않는다.
3. ingress Lambda는 명령별 공개 범위에 따라 deferred 응답에 ephemeral 플래그를 붙인다.
4. 결과 메시지는 결과 전달 Lambda가 `stage`와 `outcome`(ADR 0002)에 따라 템플릿으로 만든다. LLM이 쓴 문장은 템플릿 안의 정해진 자리에만 들어간다.
5. 메시지가 2,000자를 넘으면 잘라 내고 "전체 결과는 운영진에게 문의" 문구를 붙인다. 지원서 원문은 메시지에 넣지 않는다.
6. `allowed_mentions: {"parse": []}`는 모든 메시지에 유지한다.

## 검토한 대안

- **운영진 전용 채널 웹훅으로 스크리닝 결과 전송**: 공개 범위는 더 확실하지만 웹훅 URL이라는 비밀 정보가 하나 늘어난다. ephemeral 응답으로 충분하지 않다고 확인되면 다시 검토한다.
- **모든 결과를 채널에 공개**: FAQ는 다른 지원자에게도 유용할 수 있으나, 질문자가 원치 않는 노출이 생긴다. 공개 FAQ 게시는 운영진이 별도로 한다.

## 결과

- ingress Lambda에 명령별 권한·공개 범위 표가 들어간다. ADR 0001의 명령 목록과 같은 곳에서 관리한다.
- 결과 전달 Lambda에 단계별 메시지 템플릿과 길이 제한 테스트가 추가된다.
- 운영진 역할 ID를 환경 변수로 받는다(비밀 정보 아님).
