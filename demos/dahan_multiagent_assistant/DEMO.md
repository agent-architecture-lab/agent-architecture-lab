## 시나리오 (약 6분)

### ① 지원 전: 공식 정보 질문 — RAG (1분)

| 버튼 | 보여 줄 것 |
|---|---|
| ① 3기는 어땠나요? | 질문의 "3기"로 **기수 필터** → 3기 자료만 검색, 출처 청크 표시 |
| ① 6기 모집? | 지식 베이스에 없는 기수는 **검색 전에 거절** (5기 정보로 지어내지 않음) |
| ① 혜택 | 공지 출처 URL까지 붙은 답변 |
| ① 선발 요청 차단 | 프롬프트 인젝션 + 선발 요청을 **LLM 호출 전에 코드로 차단** |

### ② 지원 전: 추천 → 후기 → 셀프 체크 — 매칭 · RAG · Reflection (2분 30초)

| 버튼 | 보여 줄 것 |
|---|---|
| ② 스터디 추천 | 트레이스의 **추출한 라벨**(`topics=['data']`) → 코드가 20개 중 정렬. 일정·대상은 "확인 필요"로 정직하게 표시 |
| ② 이전 기수 후기 | 좋았던 점 / 어려웠던 점 / 준비 팁, **"4건 중 3건" 건수와 원문 인용**. "예시" 표시는 합성 후기라는 뜻 |
| ② 지원서 셀프 체크 | 점수 없이 항목별 판정 + 근거 인용. "목요일 참석이 어렵다"는 **숨기지 말고 문의하라**고 안내. 트레이스에서 1차 초안의 `unmatched_quote`, `prediction`(합격 가능성 언급) → 1회 수정 확인 |

말할 포인트: "추천은 LLM이 라벨만 뽑고 순위는 코드가 정합니다. 셀프 체크는 운영진용 스크리닝을 지원자용으로 바꾼 것인데, 점수를 없애고 '대신 써 주기'와 '합격 예측'을 코드로 막았습니다."

### ③ 스터디 중: 회고와 발표회 준비 — Reflection + Multi-Agent (1분 30초)

| 버튼 | 보여 줄 것 |
|---|---|
| ③ 회고 + 질문 | 한 메시지에서 **회고 → 회고 피드백**, **질문 → FAQ**로 나뉘어 실행. 회고 피드백이 지식 베이스의 다음 일정을 함께 씀 |
| ③ 힘든 회고 | 민감한 회고는 **LLM에 보내지 않고** 정해진 안내만 (호출 0회) |
| ③ 발표회 준비 | 진행 중 단계 자료(발표회 준비 안내)에서 답변 |

### ④ 끝난 뒤: 후기가 다음 기수의 자산이 됨 (1분)

| 버튼 / 설정 | 보여 줄 것 |
|---|---|
| ④ 후기 남기기(공개 동의) | 동의가 켜져 있어 **익명 저장** (스위치를 끄고 다시 보내면 저장하지 않음) |
| 역할을 "참여 예정자"로 바꾸고 ② 이전 기수 후기 다시 | 방금 쓴 후기가 **5건으로 늘어** 요약에 포함 |
| 라우팅 `supervisor` + ④ 권한 없는 요청 | Supervisor가 retro를 골랐지만 **가드가 `permission`으로 거절** → FAQ로 안내 |
| "모니터링" 화면 | 요청 수, 에이전트별 실행, 결과 분포, 가드 거절 |

## 질문이 나오면 솔직하게 말할 한계

- **시뮬레이션은 LLM이 아닙니다.** FAQ는 글자 겹침 검색(평가 31건 중 상태 정확도 87%), Supervisor는 실수를 일부러 넣은 규칙 객체, 셀프 체크·회고는 정해진 규칙입니다.
- **예시 후기 7건은 합성 데이터**입니다. 화면에 "예시"로 표시됩니다.
- 스터디 추천은 **공지의 제목과 분야 태그만** 보고 분류했습니다. 스터디별 일정·대상 정보가 들어오면 시간·수준까지 맞출 수 있습니다.
- 기수별 활동 안내와 발표회 준비 안내는 모임에서 공유한 내용을 정리한 **초안**입니다.
- 공개 웹 배포, 로그인, 후기 검토(운영진 승인), 로그 보관 정책은 아직 없습니다.
